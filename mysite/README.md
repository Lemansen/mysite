## Supabase

Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` in `.env.local`. Authenticated favorites sync through `public.favorites`; row-level security limits access to each user's rows. Guest favorites and recent/used history remain in browser storage. Never expose a service-role key in `NEXT_PUBLIC_*` variables.

## Этап 6 — персонализированная главная
- Добавлен блок «Настроить главную»: пользователь может скрывать/показывать быстрый доступ, разделы сайта, инструкцию, роли и уровни, частые вопросы.
- Настройки сохраняются в `localStorage` браузера под ключом `br_home_layout` и применяются при следующем посещении.
- Есть сброс настроек к значениям по умолчанию; адаптация под мобильные экраны.
- Существующая настройка стартового маршрута (`welcome` / `servers` / `last`) сохранена отдельно.
- Персонализация блоков хранится локально в браузере и пока не синхронизируется через Supabase.
- Проверка сборки Next.js требует запуска `npm install` и `npm run build` в окружении с доступом к зависимостям.

## Этап 8 — надёжность и резервные копии

- Добавлена страница `/backup` для скачивания JSON-копии правил, команд и промокодов текущего сервера.
- Импорт поддерживает формат резервной копии и прежний JSON с данными; проверяет структуру и ограничивает размер файла 10 МБ.
- Перед восстановлением показывается подтверждение, поскольку данные текущего сервера будут заменены.
- В шапку добавлена ссылка «Бэкап».
- Резервная копия не содержит учётные данные и ключи Supabase. Для полной защиты храните несколько копий отдельно.

Проверка `npm run build` требует установки зависимостей и должна быть выполнена локально.
